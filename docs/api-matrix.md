# Twenty CRM API and operation matrix

Twenty generates record APIs from each workspace schema rather than publishing one static record OpenAPI contract. This matrix therefore separates the current public documentation, the pinned self-hosted Twenty v2.9.0 behavior exercised by this repository, and behavior that still needs current-version live verification. Workspace-specific API documentation remains authoritative for names, fields, and permissions.

| Resource family    | Advertised operations                          | Public contract                                                      | Pinned v2.9 evidence                                                                             | Current-version status                                                                                                                                                                                                          |

Get/Get Many record operations can send optional explicit root Fields and Depth 0/1 on Twenty 2.46 and newer. Get Many uses cursor pagination, Return All/Limit, and optional raw REST filter/order expressions; field selection is retained on every page. Empty Fields preserves the prior request. Create and Update offer metadata-driven field mapping or JSON input. Record mutation retries are disabled. Generic Record workflow/workflowVersion writes are blocked after a stable Twenty version probe reports 2.47 or newer; reads, fixed resources, and unrelated objects do not probe. Unknown versions fail open for older installations and receive contextual guidance if the mutation returns 403/405. Schema mutation and automatic webhook registration are not exposed.

## Evidence boundaries

- Current human contract: [Twenty APIs](https://docs.twenty.com/developers/extend/api) and [Twenty webhooks](https://docs.twenty.com/developers/extend/webhooks).
- Current sender evidence: [`call-webhook.job.ts`](https://github.com/twentyhq/twenty/blob/ee6a5c37cd9dc420934c02cf32256234f7e96d01/packages/twenty-server/src/engine/metadata-modules/webhook/jobs/call-webhook.job.ts), [`webhook-job-data.type.ts`](https://github.com/twentyhq/twenty/blob/ee6a5c37cd9dc420934c02cf32256234f7e96d01/packages/twenty-server/src/engine/metadata-modules/webhook/types/webhook-job-data.type.ts), and [`transform-event-batch-to-webhook-events.ts`](https://github.com/twentyhq/twenty/blob/ee6a5c37cd9dc420934c02cf32256234f7e96d01/packages/twenty-server/src/engine/metadata-modules/webhook/utils/transform-event-batch-to-webhook-events.ts), accessed 2026-09-06.
- Pinned runtime: `twentycrm/twenty:v2.9.0@sha256:0afdba1494ea50bad6eb278a20ae35933317483f23501157c2ed866b74d4bc4a`; see `docs/LOCAL_TWENTY.md`.
- Modern compatibility fixtures cover the v2.35 metadata flag shape but are not a substitute for a current disposable live stack.
- Twenty Cloud and broad Twenty/n8n version compatibility are not claimed.
- Twenty 2.46 REST selection evidence: [release](https://github.com/twentyhq/twenty/releases/tag/twenty/v2.46.0), [parser](https://github.com/twentyhq/twenty/blob/twenty/v2.46.0/packages/twenty-server/src/engine/api/rest/input-request-parsers/fields-parser-utils/parse-fields-rest-request.util.ts), [default 200-field cap](https://github.com/twentyhq/twenty/blob/twenty/v2.46.0/packages/twenty-server/src/engine/api/rest/input-request-parsers/constants/rest-api-default-max-fields.constant.ts), and [selection builder](https://github.com/twentyhq/twenty/blob/twenty/v2.46.0/packages/twenty-server/src/engine/api/common/common-select-fields/common-select-fields-builder.ts). The 200-field constant applies to default root selection, not an advertised unlimited explicit selection contract.
- Twenty 2.47 workflow-write evidence: [release](https://github.com/twentyhq/twenty/releases/tag/twenty/v2.47.0) and [upstream change #27855](https://github.com/twentyhq/twenty/pull/27855).
